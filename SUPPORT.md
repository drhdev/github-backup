# Support

`github-backup` is a community-maintained project and has no guaranteed response time or paid
support channel.

- Start with the [Coolify-first README](README.md), [deployment/environment guide](docs/COOLIFY.md),
  and [logging/Uptime Kuma guide](docs/MONITORING.md). Alternative CLI installs are in
  [the CLI reference](docs/CLI.md).
- Search [existing issues](https://github.com/drhdev/github-backup/issues) before opening a new
  one.
- Use the bug-report template for reproducible operational defects and the feature template for
  proposals.
- Include the application version, Python or container version, operating system, storage mode,
  sanitized configuration, command, exit code, and relevant sanitized stdout/stderr logs.
  For Coolify include the Compose source revision, health state, and scheduler completion event.
- Never post tokens, credentials, private repository names, private URLs (including Uptime Kuma Push URLs), proprietary source,
  manifests, or backup contents.

Suspected vulnerabilities or credential/private-data exposure must be reported through the
private process in [`SECURITY.md`](SECURITY.md), not through public support channels.
